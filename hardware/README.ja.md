# ハードウェア

ロボットの機構設計と部品．

[English](README.md)

## 構成

| パス | 内容 |
| --- | --- |
| [`cad/`](cad) | 部品と組立ごとの CAD データと STEP |
| [`laser-cut/`](laser-cut) | レーザーカッター用の加工データ |
| `parts.md` | 部品表（名前，型番，数，購入先，価格）．部品が決まったら追加する． |

配線図や 3D プリント部品のフォルダは，その作業が始まるときに追加する．

## ルール

- 単位はミリメートル．
- ファイルとフォルダには部品の名前を付ける．小文字の英単語をハイフンでつなぐ（例：`chassis-base`）．`cad/` と `laser-cut/` で同じ名前を使い，加工データから元の設計をたどれるようにする．
- ファイル名に版を入れない（`-v2`，`-final` など）．ファイルを上書きしてコミットすれば，以前の版は Git に残る．
- 1ファイルは 50 MB 未満にする．GitHub は 50 MB を超えると警告し，100 MB を超えると受け付けない．それより大きいものを入れる前に相談する．
- ファームウェアは車輪の半径と左右の車輪の間隔を使う．どちらかを変えたらソフトウェア担当に伝える．
- [docs/architecture.md](../docs/architecture.md) の安全に関わる部品を設計に入れる．手が届きやすくモーターの電源を切れる非常停止スイッチと，モーターと電子回路で分けた電源系統．

## 作業の流れ

1. ブランチを作る（例：`feat/chassis-base`）．
2. 各フォルダの説明書に従ってファイルを追加・更新する．
3. 変更のスクリーンショットか写真を付けて PR を出す．
4. レビューのあと，PR が `main` にマージされる．

詳しい流れは [CONTRIBUTING.ja.md](../CONTRIBUTING.ja.md) を参照．
